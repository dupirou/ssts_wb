# 赛事对比、前端加载与文档审查

日期：2026-10-28。基线：main / b10c7f3。

## 产品范围

面向同好的小众查询站，保留原生 JS、静态构建和只读 API。无需秒级刷新或额外后台。用户已明确移除“数据未齐”等前端说明，本次不恢复这些提示，也不把这项产品决定列作缺陷。

## 已实现

- 新增具体赛事对比：两或三场、同城不同站次、跨赛季；每列先选赛季再选赛事。单场成绩页可直接加入对比，选择可通过 URL 分享和恢复。
- 把对比选择状态从 results.js 提取至 results-compare.js，使用有名称的函数处理选项、赛季联动、加载与 URL。共用既有统计模型、摘要和明细表，不增加第二套计算口径。
- 赛事模式隐藏聚合范围筛选。手机表头分行显示赛季、城市、赛事类型／站次，底层仍为原生 select；同城不同站不会丢失身份。
- 成绩脚本按栏目加载，成绩深链接预加载业务脚本；首页、赛事、运动员只请求公共脚本。成绩栏目独立于 calendar.json。
- 轻量目录移除首屏不需要的 programme 与 coverage_detail；完整明细、全量导出、摘要计算和来源证据不变。
- 删除已无渲染使用的 partial-stat、stat-definition 样式。浏览器验证产物改写到 artifacts/ui，避免每次验证覆盖历史 PR36 报告。

## 架构与可读性判断

静态构建与读 API 的分工适合当前规模。成绩模块的纯模型、请求仓库、渲染三层是清晰的；共享计算也减少前后端口径漂移。新增对比只管理对象状态，复用这些边界。

仍有维护债务：app.js 约 1,400 行，包含时钟、主题、赛程、名单和弹窗；部分旧 JS 使用密集单行写法，site.css 也有分散的响应式覆盖。这些影响局部修改的阅读成本，但当前不值得整体迁移框架或大规模格式重写。后续修改赛事交互时，再抽出数据加载和时间显示模块；调整样式时合并对应组件的规则，避免继续在末尾叠加覆盖。

## 视觉与信息密度

已查看 390 / 768 / 1440 宽度的成绩界面，并抽查首页、赛历、运动员页以及深色主题。

- 首页聚焦下一场与门票，层级明确；赛历负责找比赛，成绩总览负责进入档案，栏目职责无需重新划分。
- 成绩列表按赛事分组、阵容按需展开，对比按项目展开原始记录，信息密度符合查询型页面。双对象在手机同屏，第三对象只在表格内部横向滚动。
- 新增赛事模式最需要解决的是站名被截断，已改为城市与站次分行。没有添加解释卡片或重复大标题。
- 运动员目录当前一次渲染约 1,645 个 app 后代节点；本次未见横向溢出。数据增长后可分页，目前没有引入虚拟列表的必要。
- 继续保留真实的名次语义、A/B 组和空状态，不恢复内部诊断说明。

## 加载量

以下为构建文件的未压缩字节数，不代表公网响应时间；gzip 为本地 gzip 压缩估算，实际 CDN 编码可能不同。

| 资源 | 基线 | 当前 | 变化 |
|---|---:|---:|---:|
| 公共 site.js | 142,185 | 96,508 | -32.1% |
| 成绩 index.json | 121,677 | 48,234 | -60.4% |
| site.js gzip | 41,035 | 28,844 | -29.7% |
| index.json gzip | 10,558 | 6,552 | -37.9% |

成绩页还会加载约 52 KB 的业务脚本；新功能增加了少量总 JS，不能把公共包缩减误报为成绩页全部 JS 减少。成绩总览的数据请求从赛历加目录两次变为目录一次，数据合计从 125,926 降至 48,234 字节。无筛选时仍不加载搜索索引，展开前仍不加载原始成绩。

本地三次独立上下文测量存在波动，未据此声称固定比例的实际加载提速。保留静态页面、按需请求和有限 DOM，比新增缓存框架或服务更符合项目规模。
