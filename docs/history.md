## 统计口径

- 只计比赛当时代表 CHN 的记录，保留固定运动员身份。运动员后来转换代表协会，不回填其外协会成绩。
- `rank_scope=overall` 为最终分类名次；`rank_scope=final` 为有直接证据的 A/B 决赛组内名次。名次来源不一致时采用当前官网正式最终分类，名次、状态及奖牌统计随采用版本更新；旧决赛数据保存在 `previous_final_result`，原报告总名次保存在 `previous_reported_overall_rank`。实际 A/B 决赛参赛记录仍依据逐轮证据，不从最终名次反推轮次。
- 仅纳入个人 500、1000、1500 米及接力；世锦赛全能和个人超级 3000 均不计入成绩列表、成绩条数、奖牌、出赛、A 决赛、前八或比较。女子 3000 米接力仍正常纳入。旧档案中的超级决赛原始记录保留供追溯，构建时排除。
- 金银铜只计有效的正式奖牌项目；B 组第 1 名、PEN/DNS/DNF 等非正常完赛不计奖牌。当前统计明确限于上述项目，不宣称涵盖旧制世锦赛全能奖牌。
- 一支接力队每个项目计一条成绩、至多一枚奖牌。实际阵容缺失可以跳过，不计为成绩未齐，也不作为后续必补任务；已有队员和轮次只取当场成绩册 X 标记或比赛快照，不使用今天的队伍个人资料作为历史阵容。
- A 决赛统计实际上场的人／队次；A 决赛率为 A 决赛人／队次除以所收录项目的出赛人／队次，排除 DNS。前 8 名统计有效最终名次，组内成绩仅 A 组可计。超级决赛不重复计出赛和 A 决赛。
- 运动员表的金银铜仅统计个人项目；接力列展示其有实际出场证据的项目次数，不把团队奖牌复制到每人名下。
- 同一站同距离两赛分开保存 `race_number`。跨周期比较世界杯／世巡赛同类赛事，世锦赛、冬奥会、四大洲分别筛选，不混加原始赛季积分。
- 所有统计只覆盖已收录项目。页面对空范围显示“未收录”，没有资料不记为零。项目缺项、分类名次冲突和最终分类缺失只在数据中区分，不显示“数据未齐”或待补提示。“未设项”必须有完整的官方项目清单支持。

## 来源与身份

`catalog.json` 保存周期、赛季、赛事全局 ID 和覆盖状态；`inventory.json` 保存官方赛季目录的请求、响应指纹和赛事 ID。结果存于 `events/<competition_id>.json`。同城两站使用独立 ID。

`athletes.json` 保存稳定身份、性别、可核实别名和 ISU ID。姓名顺序只用于已登记别名匹配。新增 ISU 人物使用官方身份建立记录；PDF 新身份保存对应来源页。

PDF 结果保留官方 URL、整份 SHA-256、物理页数和逐条页码；API 结果保存请求参数、每份响应 SHA-256、赛事和项目 ID，目录指纹须与结果一致。页面每场只放一个官方来源链接。来源差异保留 `classification_conflict` 作溯源；采用当前版本后写入 `classification_resolution=current_official_classification`、采用时间及当前响应指纹，不再作为未解决冲突。

官方接口没有给出可比较的成绩修订号时，“当前版本”指本次直接读取的正式最终分类响应，不用数据库 `updated_at` 或文件抓取时间推断官方修订先后。已采用正式成绩册的档案继续保留其来源和页码。

2014/15 盐湖城官网混入 2015-02-06 的项目，已按本站 2014-11-07—09 的日期排除，保留复核记录。平昌、北京冬奥会使用 IOC 官方成绩册；2023 世锦赛使用官方成绩册的存档副本。

## 导入和维护

历史数据独立于十分钟一次的实时同步。PDF 仅供本地核验，不提交整本文件。

```sh
python tools/import_history.py 2025-26-worlds-montreal /path/to/protocol.pdf
python tools/import_olympic_history.py 2022 /path/to/ioc-results.pdf --import-records
python tools/import_history_api.py /path/to/official-calendar.json --cache /path/to/source-cache
# 定向补录；多个 --event 可组合，完整的官方赛历仍用于保持分站序号
python tools/import_history_api.py /path/to/official-calendar.json --cache /path/to/source-cache --event 1599
python tools/build.py
```

普通 C74 PDF 优先用 Poppler 的布局文本；没有 `pdftotext` 时使用项目依赖 pypdf 的 layout 提取。IOC 表仍需 Poppler，按实际文字坐标定位 FA/FB 与接力 X 列，避免普通文本压缩表头后错列。来源指纹、赛事身份、项目数量或已提取阵容的证据不匹配时拒绝导入。API 缺最终分类时，逐轮成绩只能保存实际轮次、状态和 A/B 组名次，不补造总排名。请求遇到限流、暂时服务端错误或连接超时时，最多尝试三次。

`statistics_scope` 在构建索引中公开统计范围和名次冲突处理口径；各场 `coverage_detail` 分别提供缺项 ID、未解决冲突条数、已采用当前分类的来源差异条数、缺最终分类条数和可选阵容缺失条数。`coverage` 只受项目缺项、未解决冲突和缺最终分类影响。后续优先查找原始成绩册补齐剩余四场最终分类；全能、超级 3000 和缺失接力阵容均不列入必补范围。

## 页面

`/results/` 总览；`/results/events/` 赛事成绩；`/results/cycles/` 周期包含赛季的成绩档案；`/results/compare/` 对比。周期、赛季、赛事各有独立地址，原 `/history/` 与查询链接兼容。

周期和赛季页展示金银铜、A 决赛、前 8 名、各季／各站明细、项目最佳成绩和运动员统计。对比支持两至三个具体赛事、赛季或周期；赛事模式每列先选赛季再选站次，可跨季比较。指标包括最佳名次、奖牌、A 决赛次数、A 决赛率、前 8 名；周期明细按第 1—4 赛季对齐。页面共用纯成绩模型派生的目录／赛季摘要，明细按赛事加载，不增加浏览时的上游请求；完整数据契约见 [results-contract.md](results-contract.md)。
