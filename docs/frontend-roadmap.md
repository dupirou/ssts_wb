# 前端维护计划

更新于 2026-10-28。本文区分已实现和待实施事项，不代表现有功能。

## 第一轮：已实现

- 对比默认对象从所选赛事类型中最近有收录记录的赛季／周期推导，避免年份写死；有效 URL 参数优先，仍可手动选择空赛季。切换赛事范围保留当前选择，避免用户选择被意外重置。
- `web/*.js` 与 `web/site.css` 采用固定版本 Prettier；`npm run format` 整理，`npm run format:check` 检查。格式化不承担压缩职责。
- 合并成绩页重复的字号、间距、滚动容器和表格声明，保持现有视觉与响应式行为。

## 第二轮：待实施

按后续功能需求逐项推进，不进行整站框架迁移。

1. **提取公共时间模块**：梳理 `app.js` 中日期、时区、时间格式化和赛事状态计算；将无 DOM 的计算与页面计时器分离。保持现有时区语义与边界测试。
2. **逐步拆分 `app.js`**：先独立赛事数据读取，再按赛历、名单、弹窗拆分视图；明确共享上下文和模块初始化顺序。评估成绩页是否可以进一步免载赛历专用代码，使用构建体积和实际请求验证收益。
3. **统一测试页面装配**：收拢多处重复的脚本清单、浏览器模拟和数据读取辅助函数；保留针对用户行为的断言，避免测试只重复实现逻辑。

每项独立提交，验证现有导航、分享链接、390 / 768 / 1440 像素布局以及已访问内容离线读取。无需为此增加秒级刷新、复杂恢复机制或列表虚拟化。

## 可选产品改进（不属于第二轮必做）

- URL 未指定对象时记住上次对比选择；分享链接始终优先。
- 增加双列交换操作，先确认移动端不会因此变拥挤。

保留产品决定：不恢复“数据未齐”等前端诊断说明；详情继续按需展开。
