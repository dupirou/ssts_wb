# 网站结构与历史回顾

## 页面结构

一级入口为首页、赛事、成绩、运动员。赛事内按赛季、分站浏览；分站详情再分赛程、报名名单与预测等标签。全局导航由 `web/navigation.js` 管理，分站导航不再承担全站导航职责。

| 地址 | 用途 |
|---|---|
| `/` | 当前或下一场赛事与售票信息 |
| `/events/` | 当前已收录赛季的完整赛历 |
| `/events/2026-27/vancouver/` | 指定赛季与分站；兼容原 `/?station=vancouver`，保留 day、view 等参数 |
| `/results/` | 最近正式决赛成绩；`?view=history` 查看中国队历史成绩，兼容原 `/history/` |
| `/athletes/` | 当前赛季的运动员目录与已公布世巡赛单项排名；查询条件可分享 |

`tools/build.py` 为这些地址生成真实的 index.html，CSS、脚本、数据和 SW 均使用根路径。深链接可直接打开、刷新和通过静态服务器预览；SW 继续共用一份页面外壳。

首页只加载下一场比赛的赛程。完整赛历在赛事栏目加载；成绩栏目读取小型 `/data/portal.json`；运动员索引在进入该栏目时加载。`tools/site_catalog.py` 从已验证、已格式化的比赛快照派生两个索引，不重新抓取，也不修改原始比赛记录。

## 实施顺序

第一阶段建立上述页面与导航，使用现有赛季的真实数据。运动员卡片显示姓名、协会、性别及已公布的本赛季世巡赛单项排名，不逐人重复报名链接。单站排名和往季世界排名不混入赛季排名；同一性别与距离取最新已公布榜单，榜单中已移除的选手不沿用旧名次。历史成绩独立存储于 `data/history/`，以赛季、赛事全局 ID 和固定运动员 ID 关联；当前覆盖范围见 [history.md](history.md)。

第二阶段引入多赛季数据模型：

- 用全局唯一 competition_id 标识比赛，例如 `2025-26-worldcup-montreal-1`；城市是显示字段，不再单独作为跨赛季身份。同一赛季同城的不同站次也各自独立。
- 赛季索引登记赛事及数据位置，周期索引按赛季引用，例如米兰周期对应 2022/23 至 2025/26。周期用于统计分组，不取代单场原始成绩。
- 运动员优先通过 ISU 身份及明确的别名映射关联；姓名、国籍或协会变化不拆断生涯。每次参赛当时的代表协会保留在参赛记录上。
- 历史档案和当前赛事分别构建。既有城市 ID、API 与链接保留兼容映射，渐进迁移，不一次替换所有同步脚本。

第三阶段接入中国队近三个完整奥运周期（平昌、北京、米兰），优先整理最终单项排名、A/B 决赛名单和接力实际出场阵容，再派生周期总览及项目走势。赛前报名、实际出赛、未完赛、取消赛事和资料缺失分别记录。统计可追溯到原赛事和官方来源。

跨周期展示参赛次数、奖牌及 A 决赛率，不直接比较规则不同阶段的原始积分。逐轮晋级、判罚率和选手交手记录待对应逐轮资料完整后加入。

## 历史档案现状

中国队首批档案已接入“成绩 → 历史”，收录 4 场赛事、79 条最终成绩、18 位运动员。档案按官方 C74A/B 最终分类表录入；每条记录保留成绩册物理页码，赛事保留原文 URL 与 SHA-256。接力按队伍计一次成绩，出场阵容保留每轮的实际 X 标记。

三个周期的赛季列表已登记，但完整周期回顾仍在整理。列表只统计已收录赛事；空周期显示“尚未收录”，不显示零奖牌。当前赛事 API 和数据同步保持独立。
