# 网站架构

更新：2026-10-28。本文描述已实现的页面和模块；尚未实现的方向单列在文末。

面向短道速滑同好的轻量查询站：优先保证找比赛、看成绩和比较方便，保持低维护成本。沿用静态构建、只读 API 和原生 JavaScript，不引入数据库、前端框架或秒级轮询。

## 页面职责

| 入口 | 内容 |
|---|---|
| `/` | 当前或下一场比赛、售票入口 |
| `/events/` | 赛季赛历与各站入口 |
| `/events/<season>/<id>/` | 赛程、报名、分组、逐轮成绩与预测 |
| `/results/` | 最近赛果、当前赛季与档案入口、对比入口 |
| `/results/events/<competition_id>/` | 单场中国队成绩、单项筛选、赛事来源与对比入口 |
| `/results/events/` | 周期／赛季／赛事筛选，每页最多 4 场 |
| `/results/cycles/` | 奥运周期 → 赛季的档案入口 |
| `/results/seasons/<season_id>/` | 一个赛季的各站表现、项目成绩、运动员贡献 |
| `/results/cycles/<cycle_id>/` | 一个周期的逐季表现与项目成绩 |
| `/results/compare/` | 两个或三个赛事、赛季或周期的并排比较 |
| `/athletes/` | 本赛季运动员目录与已公布排名 |

全站导航固定为首页、赛事、成绩、运动员。周期包含四个赛季，赛季包含具体赛事；“本赛季／历史”是查询条件，不重复建立栏目。`/?station=...`、`/history/`、`?view=history` 保留兼容。

## 对比交互

对比模式有赛事、赛季、奥运周期，默认仍为赛季，已有链接继续可用。

- **赛事**：每列先选赛季，再选具体一站。支持同季不同站、同城不同站次及跨季赛事；身份以完整赛事 ID 为准。此时隐藏聚合用的“赛事范围”，不会用隐藏条件过滤已选中的比赛。
- **赛季／周期**：每列选择对象，顶部选择世锦赛、冬奥会、世界杯／世巡赛或四大洲等范围。
- 对象放在表头，指标在顶部，第三个对象按需添加。重复选择保留选择器并提示更换对象。
- 所有模式共用最佳名次、奖牌、A 决赛人／队次、A 决赛率及前八算法。比例同时显示分子和分母。
- 点击项目展开构成统计的原始成绩。赛事模式只展开所选赛事；周期按第 1—4 赛季对齐。每组最多 3 场，避免一次创建全部历史 DOM。
- 单场成绩、赛季回顾和周期回顾均可携带当前对象进入对比。`mode`、`left`、`right`、`third`、`metric` 及聚合模式的 `kind` 写入 URL；赛事的所属赛季从 ID 恢复。

手机保留横向比较关系：双对象尽量同屏，第三列只在表格内部滚动，固定项目列。赛事标题比赛季长，选择器按赛季和赛事两层排列；不增加独立大卡片或解释段落。

## 模块与数据

| 层 | 职责 |
|---|---|
| `data/` 与 Python 同步脚本 | 校验并保存官方快照、身份与来源证据；复用 `tools/isu_transport.py` 请求和解析入口 |
| `tools/history_data.py` | 合并历史与当季成绩，保留原始证据 |
| `web/results-model.js` | 构建和页面共用的纯统计规则 |
| `tools/build_results.mjs` | 轻量目录、检索索引、赛季摘要、赛事明细 |
| `web/results-store.js` | 按文件缓存、请求去重、并发限制、失败重试 |
| `web/results.js` | 列表、回顾、共享统计表和原始成绩展开 |
| `web/results-compare.js` | 对比对象、赛季联动、URL 与对比视图状态 |
| `web/ui.js`、`navigation.js` | DOM、筛选序列化、路由与全站导航 |
| `web/app.js`、`portal.js` | 启动、赛程与赛事交互、首页和运动员目录 |
| `src/worker.mjs` | 已校验数据的只读 API、同步调度与健康心跳 |

单场 ID 包含赛季、类型、城市及必要站次；城市不是唯一身份。统计范围、名次、接力、DNS 等规则见 [results-contract.md](results-contract.md)，来源与历史收录范围见 [history.md](history.md)。不要在页面重新实现统计或修补原始名次。

`coverage`、`coverage_detail`、programme 和来源冲突等信息继续用于内部计算与溯源；**用户页面不恢复“数据未齐”、待补、缺最终分类等解释提示**。页面保留必要的名次语义（A/B 组）、“未收录”“未设项”“无中国队记录（0）”等空状态，避免编造数值。

## 加载与维护

- `tools/build.py` 生成公开地址的真实 HTML 外壳，支持直接打开深链接。
- 公共脚本为 `site.js`；成绩模块另编译为 `results-page.js`，只在成绩栏目加载。保持零运行时第三方依赖，源模块独立可测。
- 成绩栏目并行请求业务脚本与轻量目录，不先等待当季赛历。其他栏目不下载成绩代码或成绩索引。
- 目录不携带 programme、内部诊断或成绩行；这些仍保留于完整赛事明细。统计按所选对象的赛季加载摘要，展开才加载明细；搜索才加载检索索引。
- PWA 沿用 network-first。公共外壳预缓存，成绩脚本与访问过的数据随访问缓存；尚未访问的范围离线时允许报错重试。
- [历次审核记录](reviews/README.md)属于历史材料，不作为当前产品要求。当前维护依据是本文、frontend、backend、results-contract。

## 未实现的方向

运动员个人详情、逐轮轨迹和交手比较仍未实现，未注册 `/athletes/<id>/` 路由。后续有实际需求再加入。`app.js` 仍偏大；若继续修改赛事交互，再按数据加载、时间显示、赛程视图拆分，不为了文件行数一次重写已稳定功能。

当季赛历与成绩按赛季、赛事类型及起止日期构建唯一映射，无法唯一匹配时不显示互相跳转。上一站对比仅使用同赛季同系列编号相邻的已收录赛事。
